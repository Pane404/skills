### L10-18 交互状态全集（Interaction States）

- 判断句：把 hover/focus/active/visited/selected/disabled/readonly/loading 等作为一套有优先级的通信契约逐一设计，先列全集再定谁覆盖谁——尤其禁用态别只灰掉不说原因；L10-01 管焦点那一圈、L10-13 管 hover 冒出来的东西，本条管所有状态的清单与优先级。
- 用：设计系统为按钮/输入框/菜单项出状态规范，因缺 focus/disabled/loading 任一态都会「看着好用着坏」，需一次列全集逐态出稿；结算页「提交订单」因未填地址灰掉、保存按钮提交中，因只灰掉不说原因用户不知下一步，须 `aria-disabled`+可见说明+`aria-describedby`，提交中同时表达 loading 与禁止重复提交。
- 不用：禁用态只灰掉+`cursor:not-allowed` 不说原因、用原生 `disabled` 承载需读原因的控件 → 给可见「为什么+怎么启用」说明并 `aria-describedby` 关联，用 `aria-disabled="true"` 保持可聚焦。
  写 `button:disabled:hover`/`a:visited:hover` 矛盾组合、LVHA 打乱靠 `!important` 硬压 → 状态类独立定义 + `:hover:not(:disabled)` 显式排除、按 LVHA 声明。
- 必检：全集 default/hover/focus/focus-visible/focus-within/active/visited/selected/disabled/readonly/required/optional/valid/invalid/placeholder-shown/loading/error/success，每态出稿（B）。
  业务优先级 Disabled > Loading > Error/Invalid > Focus-visible > Active > Hover > Selected > Visited > Readonly > Default（B）。
  CSS 层按 LVHA `:link→:visited→:focus→:hover→:active`、同源特异性后声明覆盖、禁 `!important`（B/D）；优先级「业务序(来源1) vs CSS 层叠(来源5)」两层配合、`:focus-visible` 单列不并入 LVHA，属保留分歧须列各方不擅自合并（B/D）。
  `disabled`（不进 Tab/不提交/不触发）vs `readonly`（可聚焦/可复制/随表提交）、`:visited` 仅颜色类属性且隐私受限、`:invalid` 用 `:not(:placeholder-shown)` 收敛首屏不报红、loading = `aria-busy="true"`+文案+spinner 非伪类、状态叠加非替换（A/B/D）。
  焦点环不被任何状态覆盖/移除（SC 2.4.11 特有边界）按 HR-03；`aria-disabled` 可聚焦、selected 用 aria-selected/pressed/current 显式按 HR-09。
  三重表达（颜色+图标+文本）按 HR-02；loading/error/success 播报按 HR-10；hover 等价路径按 HR-07；控件命中区按 HR-01（A/B）。
