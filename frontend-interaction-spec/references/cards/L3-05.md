### L3-05 通知提醒框与通知中心（Notification / Notification Center）

- 判断句：用户当时不在场、要稍后回看与处置的异步事件用通知中心（持久存档，是让瞬时 Toast 变安全的事实来源）；说 notification 先消歧（单条提醒框 ≠ 中心、In-app ≠ OS 级 Push、Web 上常与 toast/alert 混用）→ [index/glossary.md](../index/glossary.md)。
- 用：报表页点「导出 9 月数据」后离开、10 分钟后完成，因为结果产生时用户已不在原上下文、需可回看可下载的持久入口，页内 Toast 会随页面卸载丢失（A/B）；「3 个报销单待审批」、@提及/共享邀请，因为协作事件需稍后批量处置、按来源筛选、深链跳转（B）。
- 不用：用户当前正在等的操作结果 / 纯成功确认 → 就地状态 / Toast / Alert（替代，塞进中心会凭空制造无谓待办，B）；把中心当业务数据唯一来源、或必须立即决策 → 业务对象独立状态与页面 / AlertDialog（替代，清除通知不应连带删业务数据，B）。
- 必检：`new-unseen`（新到未看、驱动 badge）/ `unread-but-seen` / `total` 三计数分离、不可揉成一个数字（A/B）；入口按钮可访问名必须含未读数（如「通知，3 条未读」），仅视觉红点对读屏不可见（SC 4.1.2/2.5.3，A）。
  打开抽屉清除新到 badge 但 unread 条目仍保留、「全部已读/清空」不删仍需下载或处置的唯一记录（B）；事件去重、深链到正确对象、权限变更后链接不泄露数据、跨设备已读同步、已读 ≠ 已完成（B）。
  每条重要 Toast / 异步结果在中心有对应可回看条目（A/B）；到达播报属分歧：社区「每条都 status 播报」(E) vs「仅重要到达播报一次」(A，SC 4.1.3)，取后者避免刷屏、不调和；到达不自动打开面板、不抢焦点。
  打开焦点移入面板标题 / 首个控件按 HR-04；Esc 关闭归还触发者，Tab 继续页面顺序，点外保留新焦点，不困焦点；面板非模态 `role="dialog"` + `aria-label`、列表 `role="list"`/<li> + `<time>`（A）；对比度按 HR-02、触控按 HR-01、ARIA 状态显式按 HR-09、动效与播报按 HR-10。
- 契约：非模态 C1 适用（打开移入）/C2 不适用/C3 适用（Esc 只关面板）/C4 按关闭原因（Esc 归还、Tab / 点外保留合理焦点）/C5 / C6 不适用；`role="dialog"` 但无 `aria-modal`、不锁背景｜详见 [contracts/overlay-contract.md](../contracts/overlay-contract.md)。
