### L3-10 错误状态与恢复（Error State / Recovery）

- 判断句：先消歧——`error state` 混三义：页面/区块级故障（本条，rejected 结论态）、字段级就地校验（见 [字段校验](../contracts/hard-rules.md#field-validation)）、
  行为契约层恢复策略（L10-15），详见 [glossary.md](../index/glossary.md)；判据 pending→加载态 / resolved 空→L3-09 / rejected→本条，重要失败一律不用一闪而过的 Toast。
- 用：列表/看板拉取返回 500 或超时、支付被拒/关键保存失败——因整块内容或高后果失败，需在原区域常驻写明原因与恢复（重试/编辑/缓存/支持）；长表单提交失败须保留全部已填内容、只标需改字段。
- 不用：① 请求仍 pending / 成功零结果 / 字段格式错 → L3-07·L3-08 / L3-09 / 就地校验（替代）；② 重要失败塞自动消失 Toast、把恢复策略与键盘焦点通则照抄进本条 → 页内持久 ErrorState / L3-01、交 L10 行为契约层（替代）。
- 必检：文案四段式（发生了什么/为什么/下一步/哪里求助）、无原始错误码与「出错了」空话、不甩锅用户（B）；不自动消失直到恢复/关闭、失败保留表单输入与筛选滚动位置、error boundary 只降级故障块（A/B）。
  不移焦点的失败状态默认用 polite。紧急且需立刻处理时才用 assertive。字段校验按表单契约，播报按 HR-10（A）。
  写请求先核对幂等键和操作状态再重试。导航 Abort 不渲染成错误，重试期间禁用按钮（D）。
  焦点/对比/触控/播报按 HR-01 / HR-02 / HR-03 / HR-04 / HR-10。
- 契约：非模态；C1–C6 不适用｜详见 [contracts/overlay-contract.md](../contracts/overlay-contract.md)
