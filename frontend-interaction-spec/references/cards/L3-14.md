### L3-14 自动保存指示（Autosave Indicator）

- 判断句：输入会持续、丢了会疼 → Autosave 常驻状态文字（正在保存/已保存+何时/失败可重试）；铁律「草稿进度 ≠ 最终提交」，Saved 只在最新相关改动成功后显示；连接/一致性态→L3-13、瞬时结论→L3-03、单次操作失败→L3-10。
- 用：长申请/多步表单（可能跨会话）、文档笔记持续输入、弱网下编辑——因丢失进度代价高，后台保草稿比让用户找远处「保存」更安全，需常驻「已保存 + 何时」让用户安心离开再回来。
- 不用：① 短表单一次性提交（登录/搜索）、支付/权限/密码/发布等敏感高后果字段 → 显式提交 + L3-03 Toast / 手动保存或 review（替代）；② 自动保存失败塞会消失的 Toast、请求未完成就写「已保存」、把 autosave 当最终提交 → 持久 Failed+Retry（L3-10）/ 先 Saving… / 独立 Submit（替代）。
- 必检：六态 initial / dirty-pending / saving / saved(+timestamp) / failed(+retry) / unsafe-to-leave；blur + 短 debounce 触发、Saved 带时间戳、按字段/分区各自状态且全部成功才给全局 Saved（B）。
  常规保存状态和可重试失败用 polite。仅在草稿面临即时丢失等紧急情形用 assertive，按 HR-10（W3C，A）。
  同一草稿串行提交或合并待发修改，或由服务端版本条件拒绝过期写入；只丢弃过期回执不足以阻止乱序写覆盖最新草稿，以刷新后仍为最新内容为验收。
  失败保持可见并给可达重试，注明草稿是否保留。有未保存改动且离开会丢失时提醒（B）。
  状态更新不抢焦点/不重置光标按 HR-04，播报与 reduced-motion 按 HR-10，Retry 键盘可达按 HR-03。
