### L4-24 嵌套浮层与堆叠管理（Nested Overlay / Stacking）

- 判断句：本条是横切浮层的栈式基础设施，但先分三类：**活动模态**（焦点困住 + 背景 inert）、**可关闭浮层**（Esc / 点外只关本层，不夺父模态焦点）、**状态播报**（Toast / live region 不进交互栈，只随活动模态可达）；嵌套 Modal 几乎总是设计失败。
- 用：编辑发票 Modal 里开 DatePicker / Combobox（非模态子层，Esc 只关子层，父模态继续负责焦点与背景阻断）、表单 Modal 退出确认层、模态内相关反馈放在活动浮层可达范围（HR-10）；外置 Toast 走状态播报豁免，不与 Dialog 共栈。
- 不用：把 Toast 与 Dialog 塞进同一交互栈、把非模态子层设为 inert，或因打开子层而停用父模态困焦 / 让父层不可操作；用 z-index 逐层加码；自动 / 路由开第二层；用第二个 Modal 推进长任务（改单 Dialog stepper 或独立页面）。
- 必检：交互栈只登记可关闭浮层，`isTopLayer()` 仅用于活动模态的焦点与 dismiss；Esc / 点外只 pop 栈顶并 `stopPropagation`，不连带关父层（HR-05），关闭后归还父层内打开它的按钮、dirty state 完好（HR-04）。
  非模态子层打开期间，父模态的 C1 / C2 / C5 保持生效；只有嵌套模态才切换活动模态并完整核对 C1–C6，且总层数 ≤2、第二层须用户动作触发、避免双层 scrim 叠黑。
  状态播报不进交互栈，也不随背景 inert 移出无障碍树；模态内消息放在活动模态的可达区域（HR-06 / HR-10）。
  滚动锁引用计数（栈空才恢复）+ 补偿宽度不跳版、`destroy()` 清理监听器（HR-06）；点外关顶层 / 底层属台账保留分歧，按技术栈定、不调和。
- 契约：横切机制的栈式判定——活动模态 C1–C6 全满足；非模态子层只适用 C3 / C4，父模态继续持有 C1 / C2 / C5 / C6；状态播报走豁免｜详见包内 [contracts/overlay-contract.md](../contracts/overlay-contract.md)。
