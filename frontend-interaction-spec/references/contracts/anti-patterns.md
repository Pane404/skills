# 禁用场景与反模式（输出前必跑）

> 目录：一、浮层类 ｜ 二、反馈类 ｜ 三、hover / 锚定类 ｜ 四、状态与文案类 ｜ 五、使用规则
> 每条都写成「不该用 → 应改用」，禁用场景必须给替代品。

## 一、浮层类

- [ ] 页面加载即弹 Modal → 改为页内呈现或不打扰用户。
- [ ] 内容超一屏 / 需 URL 可分享 / 多步 / 需前后对照，仍用居中 Modal → 页面或路由，次选 Drawer/Sheet。
- [ ] 嵌套 Dialog（两次打断说明本该是页面）→ 合并为页面流程。
- [ ] 需与列表 / 图表并排对照却用居中 Modal 盖住列表 → Drawer/Sheet。
- [ ] Popover 里出现提交按钮 → 它想要的是 Dialog。
- [ ] 弹窗含输入却允许点遮罩直接关闭并丢数据 → guarded closing 或显式确认。
- [ ] 低风险且能完整恢复的动作也逐次确认 → 执行 + 可达 Undo；有重大外部后果时保留适用的操作前保护。
- [ ] 破坏性确认只写「确定 / 取消」→ 写清对象与后果 + 明确取消出口。

## 二、反馈类

- [ ] 用短暂 Toast 承载必须处理的错误 → 按影响范围给字段就地错误、区块错误态或持久反馈，提供恢复路径。
- [ ] 普通保存成功弹 Modal → 按 [状态反馈](hard-rules.md#status-feedback) 选非阻断反馈。
- [ ] 断网反复弹 Toast 堆叠 → 常驻 Banner / Alert，恢复后自动消失。
- [ ] Toast 无堆叠上限、无统一位置 → 设上限与统一位置。
- [ ] 以视觉可见代替状态可达，或已有充分反馈仍重复提示 → 按 [状态反馈](hard-rules.md#status-feedback) 补适用语义，省略重复载体。
- [ ] 后台任务完成打断当前操作 → 走通知中心，让用户可补看。

## 三、hover / 锚定类

- [ ] Tooltip 内含链接、按钮或理解任务所必需的信息 → 纯文本化或改 Popover。
- [ ] Peek / HoverCard 里放别处拿不到的信息或复杂交互 → 信息回详情页，Peek 只做预览。
- [ ] hover-only 预览在触屏 / 键盘完全不可用 → 提供点击进详情页的等价路径（`HR-07`）。
- [ ] 延迟设 0ms 导致指针一晃闪成一片 → 按 `HR-07` 取 300–700ms。
- [ ] 只设计 Bottom Sheet 的 full 态 → peek / half / full 三档都要出稿。

## 四、状态与文案类

- [ ] 禁用态只灰掉 + `cursor: not-allowed` 不说原因 → 可见说明 + `aria-describedby`。
- [ ] 只画默认态与 hover 态，缺 focus / disabled / loading / error → 逐态出稿。
- [ ] 加载中只转圈、无文案、不置 `aria-busy` → 补文案与状态。
- [ ] 同屏出现两个 primary button → 只保留一个，其余降为 secondary/tertiary。
- [ ] 用颜色单独传达 danger / error / selected → 叠加图标、文本、ARIA（`HR-02`）。
- [ ] 导航到别的页面却用按钮 → 改 `<a href>`。
- [ ] 筛选 / 已选条件误用按钮 → 改用 Chip。

## 五、使用规则

1. 输出前检查适用条目；未通过的适用项写明原因与替代。
2. 本表属否决规则，必须在首屏可见或一次跳转可达。
3. 新增反模式必须写成可勾选项并给替代做法。
