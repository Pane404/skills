# 全局硬约束与项目基线（唯一真源）

> 目录：一、共享规则 ID ｜ 二、规则分级 ｜ 三、项目基线 ｜ 四、硬约束清单 ｜ 五、WCAG 2.2 补充

## 一、共享规则 ID（HR-xx）

卡片只写 `HR-xx` 引用，不重复数值；`HR-xx` 与 `C1–C6` 是两套独立编号。

| ID | 规则族 |
|---|---|
| HR-01 | 触控目标：标准 SC 2.5.8 AA **≥24×24 CSS px 或符合适用例外**（spacing / equivalent / inline / user-agent / essential）；项目默认 **≥44×44、间距 ≥24px** |
| HR-02 | 对比度：标准 SC 1.4.3 普通文本 ≥4.5:1、**大文本（≥18pt 或 14pt 粗）≥3:1**；SC 1.4.11 用于识别组件或状态的非文本信息 ≥3:1（按适用例外）；项目默认同标准 |
| HR-03 | 焦点环 2px、offset 2px、可见且不被遮挡；禁裸 `outline:none` |
| HR-04 | 焦点移入；关闭按原因处理：Esc / 选中归还触发者，Tab 继续顺序，点外保留新焦点，不掉回 `<body>` |
| HR-05 | Esc 只关最顶层；点外关闭；轻关闭监听用 `pointerdown` |
| HR-06 | 模态需要实际阻断背景并管理焦点；原生 `showModal()` 提供模态机制，自定义浮层按实际行为判定。渲染层级、关闭、滚动锁分别核对 |
| HR-07 | hover 延迟 300–700ms 禁 0ms；hover-only 必须给点击 / 键盘 / 触屏等价路径 |
| HR-08 | 可安全错过且别处可达的 Toast 默认 3–5s；操作型反馈在动作有效期间可见，或另给等价的持久可见入口 |
| HR-09 | 原生元素优先、ARIA 状态显式、可见 `<label>` |
| HR-10 | 状态消息与动效：**SC 4.1.3（AA）适用的状态消息应在不移动焦点时可被辅助技术感知（证据 A）**；项目默认 `prefers-reduced-motion`、live region polite 优先、文案动词开头 |

## 二、规则分级（Floor / Default / Finish）

- **Floor（不可协商）**：HR-01 的 24×24 地板与例外、HR-02 对比度、HR-03 焦点可见、HR-06 模态性、HR-09 原生语义、**HR-10 的 SC 4.1.3 状态消息**——违反即不可交付，用户偏好不得覆盖。
- **Default（可覆盖留痕）**：HR-01 的 44×44、HR-07 hover 300–700ms、HR-08 Toast 3–5s——随平台 / 库调整，须注明采用层与理由。
- **Finish（表达细节）**：动效与文案形式按场景选。适用的焦点归还、Esc 等行为按横切契约核对。

用户要求与 Floor 冲突时，说明冲突并给满足合规的最小替代，**不得静默降级**。

## 三、项目基线（5 组已裁定）

| 项 | 适用标准（合规地板） | 项目默认 | 可否覆盖 |
|---|---|---|---|
| 触控目标 | SC 2.5.8 AA ≥24×24 CSS px 或符合适用例外 | ≥44×44，间距 ≥24px | 默认可调整，合规底线适用 |
| 对比度 | SC 1.4.3 普通文本 ≥4.5:1、大文本 ≥3:1；SC 1.4.11 ≥3:1 | 同左 | 否 |
| 焦点环 | SC 2.4.7 可见、SC 2.4.11 不被遮挡 | 2px、offset 2px | 部分可（可见性不可覆盖） |
| Toast 时长 | 限时内容按适用的 SC 2.2.1 处理 | 轻提示 3–5s；操作型反馈按 HR-08 | 可 |
| hover 延迟 | 无强制合规约束；等价路径不可取消 | 300–700ms 禁 0ms | 可 |

## 四、硬约束清单（输出前逐条勾）

- [ ] 命中区与间距按 `HR-01`；移动端输入框字号 ≥16px，避免 iOS 自动缩放。

**颜色与可读**
- [ ] 对比度按 `HR-02`；error / selected / disabled 不得只靠颜色表达，须叠加图标 + 文本 + ARIA 状态。

**焦点与键盘**
- [ ] 焦点环按 `HR-03`；焦点管理按 `HR-04`。
- [ ] 优先使用原生元素（`<button>` / `<a href>` / `<input>`），不用 `<div>` + `role` 伪造（`HR-09`）。
- [ ] Enter 与 Space 都能激活按钮；链接只响应 Enter。

**语义与命名**
- [ ] 纯图标按钮必须有 `aria-label`；带文字的图标对读屏 `aria-hidden`。
- [ ] 必须有可见 `<label for>`；placeholder 不代替标签。
- [ ] 状态用 `aria-disabled` / `aria-busy` / `aria-invalid` / `aria-selected` 显式表达。

<a id="status-feedback"></a>**状态反馈与动效**
- [ ] 已有充分且可访问的结果、必要操作也可达时省略额外提示。原位更新若尚不能由辅助技术感知，先补适用的状态语义，焦点留在任务中。
- [ ] 需播报时可用预先挂载的 live region，常规状态用 polite，紧急状态才用 assertive；不按 danger 颜色直接选 `role="alert"`，已聚焦的错误摘要不再叠 alert 抢播，避免同一更新重复播报（`HR-10`）。
- [ ] 动效遵循 `prefers-reduced-motion`；减少动效时焦点环、禁用原因、错误文本不得消失。

- [ ] 标签以动词开头、1–4 词、句式大小写、点明对象；禁用「确定 / OK / 提交」这类空文案。
- [ ] 破坏性动作写清对象与后果（「删除工作区及其中 12 个项目」）。
- [ ] 方向性词（「上方 / 右侧」）会损害读屏与 RTL，改用就近标签。

<a id="field-validation"></a>**表单与字段校验**
- [ ] 已输入或修改的字段首次可在失焦时校验；错误出现后随修改复校，改对即清除。提交时全量复校，保留已填内容。
- [ ] 错误贴字段、持续到修正，并用 `aria-invalid` 和 `aria-describedby` 关联现有错误文本。提交失败时聚焦首错，或聚焦可导航的错误汇总。
- [ ] `autocomplete`、type / inputmode 与内容匹配；区分 `readonly` 与 `disabled`。服务端仍复校；提交中禁用按钮不能替代幂等。

## 五、WCAG 2.2 补充（证据等级 A）

- [ ] SC 2.4.11 焦点不被遮挡（AA）：**获得键盘焦点的组件不得被作者内容完全遮挡**（部分遮挡允许）；项目默认更严——浮层 / 吸顶不得盖住焦点。
- [ ] SC 2.5.7 拖放动作（AA）：拖放必须提供单一指针的等价替代路径；例外为 essential 或由 user agent 决定。
- [ ] SC 2.5.8 的 spacing 例外：以各偏小目标的包围盒中心画直径 24 CSS px 的圆，圆不能与其他目标或其他偏小目标的圆相交。
- [ ] SC 3.2.6 一致帮助（A）：帮助入口在多页间保持相同相对位置。
- [ ] SC 3.3.7 冗余输入（A）：同一流程中已提供的信息可自动填入或供选择，按必要、安全、信息已失效的例外处理。
