# 级联优先级与覆盖规则

> 目录：一、四层优先级 ｜ 二、按规则性质裁决 ｜ 三、不可覆盖 ｜ 四、5 组基线 / 7 组分歧

## 一、四层优先级（低 → 高）

| 级 | 名称 | 内容 |
|---:|---|---|
| 1 | 外部基础规范 | W3C / WCAG / WAI-ARIA APG / MDN / HTML 标准 |
| 2 | 平台 / 设计系统约定 | Material 3、Apple HIG、Ant Design、Carbon、Radix 等 |
| 3 | 项目基线 | 本项目选定的默认取值与文案口径（见 `../contracts/hard-rules.md`） |
| 4 | 当次任务约束 | 用户明确指定的平台、品牌、无障碍等级、技术栈 |

## 二、按规则性质裁决

1. **先钉死合规地板**：确定任务适用的规范与合规目标（如 WCAG 2.2 AA）。
2. **再谈偏好**：在地板允许范围内，依次应用库约定 → 项目默认 → 当次偏好。
3. **覆盖留痕**：高层仅在明确声明时覆盖低层，须记录采用的层、理由、背离方。

## 三、不可覆盖

合规类规则（WCAG AA 条款、焦点 / 键盘可达性、焦点不被遮挡）**不受当次偏好覆盖**。
用户要求与合规地板冲突时，说明冲突并给出满足合规的最小替代，不得静默降级。

## 四、5 组基线 / 7 组分歧

**已裁定（给单值）**：见 `hard-rules.md` §三 的 5 行基线（对应 HR-01 / HR-02 / HR-03 / HR-07 / HR-08）。
**保留分歧（列各方取值与证据等级，不擅自取单值）**：纯黑 OLED、M3 是否弃用 drawer、Radix 菜单模态性、Snackbar 具体时长、Peek 尺寸、点遮罩关闭、点外关顶层 / 底层。

> 两处「5 / 7」是**不同集合**：本节指项目基线的 5 行与保留分歧的 7 项；`../topics/conflicts-and-evidence.md` §一 指原库 12 组冲突的复核状态。输出时按**条目编号**查台账（如 `#c6`），不要按数字记忆。
