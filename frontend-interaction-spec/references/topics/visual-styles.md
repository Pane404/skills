# 视觉流派与风格配方（C 级专题）

> 按「风格族 → 判断句 → 不用 → 检查要点」组织；风格选择与组件选型正交，命中时整份读。

### L9-01 minimalism-swiss
- 判断：用严格的数学栅格、单一无衬线字族与高对比留白，把视觉噪音降到零，让信息层级本身承担全部表达。
- 不用：儿童教育、游戏、娱乐、玩具品牌 → 需要情感、角色、高饱和多色 → L9-17 孟菲斯 / L9-08 黏土拟态 / L9-27 极繁主义
- 必检：检查全站只用 1 个无衬线字族（最多 2 个）与 400/700 两档字重。
### L9-02 flat-design
- 判断：去掉阴影、渐变、纹理等一切拟物深度，用纯色块、几何形与字阶在单一平面上建立层级，换取跨设备一致与极快渲染。
- 不用：奢侈品、酒店、高端餐饮、手工品牌 → 需要质感、纹理、摄影深度来传达档次，纯色显得功利廉价 → L9-04 拟物化 / L9-20 编辑杂志风
- 必检：检查全站 `box-shadow:none`、`background-image:none`、圆角 ≤4px，无渐变与纹理。
### L9-03 material-design
- 判断：以"数字纸张 + 高度阴影"表达层级、以算法生成的动态色角色保证对比度，是扁平与拟物之间带回可供性的完整体系化解法。
- 不用：品牌色受严格法务管控的企业 VI（金融/政务/奢侈品牌） → 因为 dynamic color 会把品牌主色替换成壁纸派生色 → 固定品牌主题或 L9-01 瑞士极简
- 必检：检查所有颜色取自语义 roles（primary/on-primary/surface…），且暗主题单独校验对比度。
### L9-04 skeuomorphism
- 判断：让界面元素模仿真实物件的材质与光影（皮革/木/金属/旋钮），用用户已有的物理经验直接换取"这是什么、怎么操作"的理解。
- 不用：现代企业后台、金融交易终端、数据密集 SaaS → 因为纹理与写实阴影制造视觉噪音、拖慢扫描与渲染 → L9-02 扁平化 / L9-01 瑞士极简
- 必检：检查每处写实细节都对应一个真实、用户认识、且当前仍存在的物理隐喻。
### L9-05 neumorphism
- 判断：让元素与背景完全同色，仅靠一对等距反向的明暗阴影模拟"从表面挤出/压入"，以极简单色换取柔和触感——但这是一条结构性违反 WCAG 非文本对比的高争议风格。
- 不用：支付 / 提交 / 删除等关键操作、金融 UI、政务医疗合规界面 → 因为控件边界对比≈1:1，违反 WCAG 1.4.11（3:1），关键操作必须高对比 → L9-02 扁平 高对比实心按钮 / L9-03 Material
- 必检：检查元素 `background` 与父容器**完全相等**，且未用在纯白/纯黑底上。
### L9-06 glassmorphism
- 判断：用半透明填充 + `backdrop-filter` 背景模糊 + 发丝边框 + 柔阴影，让面板像磨砂玻璃浮在彩色内容之上，以"透出背后"表达层级。
- 不用：数据表格、电子表格、长文阅读、表单字段 → 因为"没人愿意透过模糊去读数字"，且模糊降低扫读 → 实心卡片 + 柔阴影 / L9-02 扁平
- 必检：检查玻璃面板自身 `background` 是 `rgba()` 半透明（不是 `opacity`），且背后有饱和渐变/照片可模糊。
### L9-07 liquid-glass
- 判断：Apple 于 WWDC 2025 推出的系统级材质，让界面像真实光学玻璃那样**折射**下方内容、捕捉随设备方向变化的镜面高光、并在交互时流动形变——Web 只能用 CSS/SVG 近似，且必须自带对比度与透明度回退。
- 不用：数据密集表格、长文阅读、表单、内容卡片本身 → 因为 Apple 自己就避免"内容卡片玻璃化"，折射会伤害可读性 → 实心卡片 / L9-01 瑞士极简
- 必检：检查液态玻璃只用在 ≤3 个 hero/工具栏表面，没有把内容卡片本身做成玻璃。
### L9-08 claymorphism
- 判断：用「一大柔外投影 + 一深一浅两道内阴影」的三层配方叠在超大圆角的不透明粉彩表面上，做出像橡皮泥捏出来的膨胀体——是对新拟态低对比缺陷的高对比修正。
- 不用：数据密集仪表盘、企业 admin 表格、搜索结果、法律/合规文案 → 因为大圆角 + 厚阴影 + 低密度与"精确、可扫读"冲突 → L9-02 扁平 / L9-01 瑞士极简
- 必检：检查每个黏土元素都有外投影 + 白色 inset 高光 + 深色 inset 三层阴影，缺一即补。
### L9-09 brutalism
- 判断：借 1950–70 年代「béton brut 清水混凝土」建筑的态度，把网页的原始 HTML 结构、默认字体、生猛黑白与刻意的粗糙直接暴露出来——用"拒绝打磨"表明立场。
- 不用：银行 / 保险 / 法律 / 诊所 / 政府 / 养老 / 医疗健康 → 因为访客带着焦虑来、需要"能力感与传统可靠"，粗野会被读成"坏了或业余"并直接离开 → L9-01 瑞士极简 / L9-20 编辑杂志风
- 必检：检查全站是语义 HTML，禁用 CSS 后标题/列表/链接/阅读顺序仍成立。
### L9-10 neubrutalism
- 判断：保留野兽派的粗黑描边、零模糊硬偏移阴影、高饱和撞色与巨大粗体字，但把底层布局做成干净、可用、面向转化——"大胆却亲和"的商业化演进。
- 不用：银行 / 保险 / 政府 / 医疗服务 → 因为信任必须靠冷静、传统、专业传达，响亮配色与攻击性粗边读作"不严肃"，且无障碍合规强制 → L9-01 瑞士极简 / L9-03 Material
- 必检：检查全站只用 2–3 个饱和色 + 1 个边框权重（3px）+ 1 个阴影偏移（5px 零 blur），且 `border-radius:0`。
### L9-11 bento-grid
- 判断：以大小不一的圆角卡片拼成非对称马赛克，用「格子尺寸直接编码重要性」建立层级，配合中性底、柔和阴影与克制的 hover 抬升，形成 Apple 式精致展示质感。
- 不用：密集数据表、实时监控、复杂表单 → 因为便当格是"展示型"而非"录入/比对型"，格子会打断逐行扫描与精确对齐 → L6-01 表格 / L9-02 扁平
- 必检：检查用 CSS Grid（`repeat(4,1fr)` + `span`）实现，没有用绝对定位堆格子。
### L9-12 aurora-gradient-mesh
- 判断：在近黑画布上叠 3–6 个大而柔的高饱和径向渐变色团，让它们以 8–20 秒缓慢漂移并覆一层噪点，模拟北极光的流动辉光——用"活的渐变"营造高端氛围。
- 不用：数据界面、仪表盘、实时监控、后台 → 因为流动色团与"聚焦、精确"争夺注意力，且模糊/动画耗 GPU → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查底色为近黑 `#030308–#0a0a1a`，色团 3–6 层、单层 opacity 0.3–0.6、总可见 ≤1.5、色板 ≤4 色。
### L9-13 dark-oled
- 判断：为 OLED/AMOLED 面板把背景推到接近 `#000000`（像素完全关闭、零功耗），以硬件特性换取省电与极致对比——代价是散光用户的 halation 光晕与滚动拖影，必须配 off-black 与可切换档位。
- 不用：桌面优先 / LCD 屏为主 / 混合设备产品 → 因为 LCD 背光恒亮、纯黑**无省电**且易 smearing，标准深灰更稳 → L0-15 标准深灰令牌 / 浅色主题
- 必检：检查主背景 `#000000` 但内容面留 1–2% 亮度差（`#0a0a0a–#121212`），没有把纯黑铺到所有表面。
### L9-14 cyberpunk-neon
- 判断：把屏幕当成"雨夜城市里焊起来的破旧 HUD"——近黑底 + 青/洋红/黄的霓虹辉光 + 等宽终端字 + 切角面板 + 扫描线 + glitch，用"露出线路、闪烁不稳定"传达高科技低生活的反乌托邦气质。
- 不用：企业 / 政务 / 医疗 / 金融 / 家庭 App / 老年用户 → 因为"不友好、不稳定、反权威"的语义与信任、清晰、安抚完全相反 → L9-01 瑞士极简 / L9-03 Material
- 必检：检查底色为近黑 `#0D0D0D/#0a0a0f`、霓虹色令牌化、等宽正文 + 窄体标题。
### L9-15 vaporwave
- 判断：用粉紫青的落日渐变、透视网格、CRT 扫描线、glitch 与 Win95 系统 UI 元素，拼贴出"对一个从未存在的 80–90 年代消费乌托邦"的怀旧反讽——氛围优先于效率。
- 不用：企业 / 商务 App、B2B SaaS、医疗记录、教育、电商转化流程 → 因为"氛围优先于效率"、怀旧反讽与专业/信任/精确相反 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查落日渐变色板（`#FF71CE/#01CDFE/#B967FF/#05FFA1`）令牌化，渐变只铺背景 + 1–2 个 hero 元素。
### L9-16 y2k
- 判断：复活 1997–2004 年的"合成未来主义"——液态 chrome 金属字、虹彩全息面、果冻光泽按钮、pill 形控件、亮青洋红与 techno 宽体字，传达早期互联网对机器与赛博空间的乐观。
- 不用：金融服务、医疗、法律、B2B 软件、文档站 → 因为"信任是首要任务"，chrome 标题压在亮渐变上会把视觉语言推到用户与信息之间 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查 chrome 渐变有硬中停、chrome 字用 `background-clip:text` + `color:transparent`，并配暗底板/描边或真实高对比副本。
### L9-17 memphis
- 判断：1981 年 Ettore Sottsass 米兰小组对米色极简的反叛——用冲突撞色、三角/圆/波浪等几何形、点纹条纹、刻意倾斜与非对称、粗描边与硬偏移阴影，把"受控的混乱"做成玩趣的后现代语言。
- 不用：企业金融、医疗、法律、保险、老年用户、保守品牌 → 因为"玩趣/不严肃"与信任、稳重、清晰相反 → L9-01 瑞士极简 / L9-03 Material
- 必检：检查色板 ≤3–5 个撞色、全平色无渐变、圆角 ≤2px、硬偏移阴影零 blur。
### L9-18 retro-pixel
- 判断：以低分辨率像素画、有限调色板、锐利边缘与逐帧动画复刻 8/16-bit 街机与 CRT 终端——"约束即美学"，但像素字体、扫描线与闪烁是真实的可读性与光敏风险。
- 不用：现代企业、现代 SaaS、高分辨率摄影站、专业精确工具 → 因为"CRT 终端读作黑客周边、Win95 读作反讽"会与"把事做完"争抢注意力 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查 `image-rendering:pixelated`、仅 2x/3x/4x 整数倍缩放、无抗锯齿、`border-radius:0`、硬阴影零 blur。
### L9-19 organic-biophilic
- 判断：借 biophilia（亲生命性）假说，用 blob 有机形、叶弧与波浪分隔、大地色、纸/木/石纹理与缓慢呼吸感动效，把自然的形式语言引入界面，营造"被照料、可恢复"的温暖气质。
- 不用：数据密集界面、开发者工具、精确 / 事务型应用、企业金融 → 因为有机形不如矩形可预测、在专业语境显不专业、与"精确"相争 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查用 blob（`border-radius:60% 40%…`）/ SVG 波浪（`viewBox`+`preserveAspectRatio="none"`）/ 16–24px 圆角构成有机形。
### L9-20 editorial-magazine
- 判断：把印刷杂志的排版语汇移植到 Web——非对称栅格、大图、衬线正文配粗无衬线标题、首字下沉（drop cap）、引言（pull quote）、署名与分栏——用"阅读的仪式感"服务长文。
- 不用：仪表盘、App 功能 UI、电商目录、实时数据、短内容 → 因为 drop cap / 多栏 / 大图会拖慢扫读，事务型界面要速度与清晰 → L9-02 扁平 / L9-01 瑞士极简
- 必检：检查用 `::first-letter` 实现 drop cap（非拆词 span），作用域为 `.article-content > p:first-of-type`，全篇仅一处。
### L9-21 kinetic-typography
- 判断：让"文字本身成为视觉"——超大标题随视口缩放、随滚动改变字重/字距、逐字逐行揭示或可变字体 morph，把消息直接做成首屏的主角，替代传统的"图 + 居中标题"hero。
- 不用：高度务实 / 年长 / 紧迫转化受众（紧急服务、部分 B2B 采购流程） → 因为"清晰胜过剧场"，静态大标题 + 证据点转化更好 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查 H1 是唯一、稳定、可被爬虫/读屏读取的真实文本，关键词写在 H1 里而非图片。
### L9-22 motion-driven
- 判断：把滚动位置当作动画时间轴（`animation-timeline: scroll()/view()`），让视差、sticky 叙事、进度条与分区揭示随滚动同步演进——用运动解释空间与变化，但默认必须"没有动效也完整可读"。
- 不用：结账 / 注册 / 文档 / 表单 / 长文页面（内容需随时可读） → 因为"内容隐藏到精确滚动位才出现 = 不可见内容"，禁把主内容做 reveal → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查基础态 `opacity:1; translate:none`（内容默认可见），动画只在 `@supports (animation-timeline:…)` 内启用。
### L9-23 3d-hyperrealism
- 判断：用 Three.js / Babylon.js / WebGL(WebGPU) 渲染带 HDRI 光照、物理材质与软阴影的真实感 3D 物体，让用户在买前"拿起来转一转"——沉浸的代价是把一个渲染引擎发给每位访客。
- 不用：SaaS 落地页 hero 只因为"看起来酷"（发光 3D orb） → 因为移动端掉帧 / 跳出率上升，装饰 wow 无回报 → L9-12 极光渐变（更轻）/ L9-01 瑞士极简
- 必检：检查 3D 通过具体业务目标（产品理解 / 转化 / 遗产展示）验证，不是"只因为酷"。
### L9-24 spatial-ui
- 判断：为 Apple Vision Pro / visionOS 设计"漂浮在真实房间里的玻璃面板"——用克制的 z 轴深度表达层级、以眼动定位 + 捏合确认输入、以世界锚定保证舒适，而不是把 2D 窗口搬进头显。
- 不用：文本密集文档、长文阅读、高对比强制界面 → 因为玻璃对未知背景、避免文本深度、thick 材质仍不如实底稳 → L9-20 编辑杂志风 / L9-26 电子纸
- 必检：检查用系统玻璃材质（非实色）、vibrancy + 白字/系统色、thick 材质用于阅读面、嵌套圆角同心。
### L9-25 ai-native-ui
- 判断：为"非确定性、有延迟、会自信地出错"的系统设计的界面契约——流式输出、可见的不确定性、常显的 AI 标识、可编辑草稿、来源引用、可撤销与人工确认，把概率性输出包装成可信赖的协作。
- 不用：结构化输入（申请表单、筛选、设置、结账） → 因为意图已知，表单更快更可靠、可校验 → L2-07 表单 / L8-05 结算
- 必检：检查首 token 几百 ms 出现、Stop 最显眼且 Tab 可达、`aria-busy` 随 streaming 切换、完成后去光标并 focus Retry。
### L9-26 eink-paper
- 判断：把界面当"不发光的纸"——暖白哑光底 + 墨黑文字、近单色、零动效、分页阅读、极简 chrome，用 Calm Technology 的克制换取长时间专注与几乎无损的可访问性。
- 不用：游戏、视频平台、高能量营销、暗色模式依赖的 App → 因为"安静、慢、去刺激"和这些品类要的能量 / 沉浸相反，且本条几乎无深色版 → L9-14 赛博霓虹 / L9-12 极光渐变
- 必检：检查底色为暖白 `#FDFBF7/#FAFAF8`（非纯白）、文字 `#1A1A1A`、单一高亮黄只给可操作元素。
### L9-27 maximalism
- 判断："more is more"——用密集信息、分层元素、混排字体、撞色、碰撞栅格与 pattern-on-pattern 主动拒绝"少即是多"，但把丰盛架在栅格 / 字系 / 色逻辑之上，让"多"读成丰富而非噪音。
- 不用：实用工具、高信任服务（金融 / 医疗 / 政务）、需快速扫读的确定性任务 → 因为"清晰规则"，密集分层会拖慢任务完成 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查有刻意层级（主 CTA 3 秒内可识别）、70-25-5 配色、单组件 >5 色已分语义角色并做色盲模拟。
### L9-28 anti-design
- 判断：作为对"算法化完美 / 模板化极简"的反动，故意打破惯例——冲突色、混排字、非对称与刻意"缺陷"——但启发式仍适用，只是被**表达性地**应用：反叛在执行，不在放弃原则。
- 不用：速度与效率为首要目标、高压下依赖可预测模式的场景 → 因为表达会变成噪音，用户要的是零摩擦 → L9-01 瑞士极简 / L9-02 扁平
- 必检：检查核心导航清晰、主路径可达、核心消息在杂乱中仍可理解、"反叛在执行不在放弃原则"。
### L9-29 hud-scifi
- 判断：源自电影"让虚构科技可信"的 FUI（Fantasy User Interface）——细线线框、圆阵雷达、单色 + 警示红、等宽大写技术字与角括号坐标，做"战术、精确、分析性"的仪器盘；glanceability 优先，但细线与发光天生不友好。
- 不用：标准企业 UI、阅读密集内容、无障碍公共服务 → 因为 1px 细线 + 全大写等宽 + 发光 = Poor 可访问性，长文不可读 → L9-01 瑞士极简 / L9-26 电子纸
- 必检：检查底色 `#000b18` / 透明、单色主 hue（青/琥珀/绿）、红仅用于 alert、深度靠 opacity 非阴影。
### L9-30 zero-interface
- 判断：让界面退到后台——用语音、手势、传感器、上下文与 AI 预测把"导航菜单"替换为"直接达成意图"，去掉的是不必要的界面，不是交互、反馈与控制权。
- 不用：需大量比较 / 视觉探索 / 详细编辑 / 复杂信息分析 → 因为无屏无法承载比对与精修，视觉界面在这些任务仍最优 → L6-01 表格 / L9-20 编辑杂志风
- 必检：检查以"用户意图"而非"按钮"为设计起点，且自动化确实减少 effort（非为未来感）。
